# Ασκήσεις και πρόγραμμα — 0.3.0 / 0.3.1

Η λειτουργική ροή βρίσκεται ολόκληρη στην ενότητα **Πρόγραμμα**: βιβλιοθήκη ασκήσεων, δημιουργία/επιλογή προγράμματος, οργάνωση προπονήσεων. Η τελική αισθητική θα παραδοθεί από τον agent εμφάνισης. Η έκδοση εργασίας είναι 0.3.1· δεν έχει γίνει deployment. Κατά τον έλεγχο ο ένας λογαριασμός είχε ήδη συγχρονίσει το νέο μοντέλο μέσω της εφαρμογής. Δεν εκτελέστηκε μαζική αντικατάσταση των snapshots από εργαλεία SQL.

## Μοντέλο και κανόνες διατήρησης

| Πεδίο | Ρόλος |
|---|---|
| `trainingExercises[]` | Συγχρονισμένη προσωπική βιβλιοθήκη. Κάθε ορισμός έχει `id`, `name`, `notes`, `aliases`, `updatedAt`. |
| `plan[].exerciseId` | Αναφορά στον ορισμό της άσκησης. |
| `plan[].id` | Ανεξάρτητη θέση στο πρόγραμμα. Δύο εμφανίσεις της ίδιας άσκησης έχουν διαφορετικά slot IDs. |
| `session.exercises[].exerciseId` | Ίδια ταυτότητα άσκησης σε διαφορετικές ημέρες και προγράμματα. |
| `session.exercises[].planExerciseId` | Η θέση προγράμματος από την οποία προήλθε η συγκεκριμένη καταγραφή. |
| `session.exercises[].exercise` | Το ιστορικό όνομα όπως καταγράφηκε. Δεν ενημερώνεται από μετονομασίες της βιβλιοθήκης ή αλλαγές προγράμματος. |

Τα σετ και τα cues ανήκουν στη θέση του προγράμματος, όχι στον κοινό ορισμό. Η βιβλιοθήκη επιτρέπει χωριστούς ορισμούς με ίδιο όνομα· οι επιλογείς εμφανίζουν αρίθμηση και σημειώσεις για να διακρίνονται. Δεν υπάρχει διαγραφή/συγχώνευση ορισμών σε αυτή την έκδοση.

Το `modules/exercises.js` παρέχει καθαρές συναρτήσεις για migration, δημιουργία/επεξεργασία, ταυτότητα και εμφάνιση. Η εφαρμογή εμφανίζει το τρέχον όνομα από τη βιβλιοθήκη στο πρόγραμμα και στις νέες προγραμματισμένες καταγραφές. Το Ιστορικό συνεχίζει να χρησιμοποιεί τα αποθηκευμένα ονόματα.

## Μετάβαση

1. Διαβάζονται οι υπάρχοντες ορισμοί, τα προγράμματα και το ιστορικό. Δεν χρησιμοποιείται στατικός κατάλογος demo ασκήσεων.
2. Γίνεται αντιστοίχιση ακριβών ονομάτων μετά από περιφερειακό trim, με deterministic `legacy:` IDs. Πεζά/κεφαλαία, τόνοι και παρόμοια ονόματα παραμένουν χωριστά. Ομώνυμες legacy εγγραφές χωρίς άλλη ταυτότητα θεωρούνται μία άσκηση. Υπάρχοντα διαφορετικά `exerciseId` δεν συγχωνεύονται.
3. Σε ομώνυμους ορισμούς, χρησιμοποιείται η θέση του προγράμματος μόνο όταν και το ιστορικό όνομα συμφωνεί. Αμφίσημη καταγραφή παίρνει χωριστή `ambiguous:` ταυτότητα, χωρίς εικασία.
4. Οι μετονομασίες κρατούν aliases, ώστε ένα παλιό snapshot να αντιστοιχίζεται ξανά στον ίδιο ορισμό. Τα αρχικά πεδία ιστορικού, τα IDs προγραμμάτων/καταγραφών και τα tombstones διατηρούνται.
5. Πριν από τις εγγραφές migration δημιουργείται το `logbookExerciseMigrationBackup`: ακριβή raw αντίγραφα των πέντε domain keys, με owner marker. Αν αποτύχει το backup ή η αρχική εγγραφή βιβλιοθήκης, οι επόμενες domain εγγραφές μπλοκάρονται μέχρι επανεκκίνηση με διαθέσιμο χώρο. Η σειρά είναι backup → βιβλιοθήκη → αναφορές. Μια διακοπή ενδιάμεσα επιτρέπει επανάληψη χωρίς νέες ταυτότητες.

Το backup είναι τοπικό βοήθημα ανάκτησης της μετάβασης, όχι πλήρες user-facing export. Καθαρίζεται στο sign-out μαζί με τα domain keys. Τα user-scoped cloud recovery caches διατηρούνται σύμφωνα με την υπάρχουσα πολιτική. Πριν από παραγωγική αναβάθμιση απαιτείται ανεξάρτητο εξαγόμενο αντίγραφο του πραγματικού Supabase snapshot.

## Συγχρονισμός και παραγωγή

Η βιβλιοθήκη συμμετέχει σε payload normalization/hash, meaningful-data detection, merge, guest import και account isolation. Οι ορισμοί συγχωνεύονται ανά ID, με `updatedAt` για τις αλλαγές και διατήρηση aliases. Νεότερο remote snapshot που παραλείπει τη βιβλιοθήκη ανακτά τους ορισμούς από το αντίγραφο του ίδιου owner, διατηρώντας τις remote καταγραφές.

## Παράδοση στον agent εμφάνισης

Η νέα φόρμα βρίσκεται πριν από το `.routine-manager` μέσα στο `#plan-view`. Τα νέα styles είναι περιορισμένα στο `.exercise-library`. Η εμφάνιση μπορεί να αντικατασταθεί διατηρώντας τα παρακάτω hooks ή προσαρμόζοντας ρητά τους listeners και τα browser tests:

| Hook | Λειτουργία |
|---|---|
| `#exercise-library-form` | Submit δημιουργίας ή επεξεργασίας· `data-editing-id`, `data-dirty` κρατούν context. |
| `#library-exercise-name`, `#library-exercise-notes` | Όνομα και σημειώσεις. |
| `#exercise-library-list`, `[data-edit-exercise]` | Λίστα και επιλογή επεξεργασίας ανά ID. |
| `#cancel-library-edit`, `#exercise-library-status` | Ακύρωση και προσβάσιμη ανακοίνωση αποτελέσματος. |
| `.plan-exercise-fields[data-plan-id] .builder-name` | **Select με value=`exerciseId`**, όχι όνομα. |
| `.builder-sets`, `.builder-cues` | Ρυθμίσεις συγκεκριμένης θέσης προγράμματος. |
| `[data-open-exercise-library]` | Έξοδος από τον άδειο day editor στη δημιουργία άσκησης. |
| `[data-exercise][data-exercise-id][data-plan-exercise-id]` | Αναφορές της Καταγραφής και του workout draft. |
| `.session-library-exercise` | Προαιρετική επιλογή βιβλιοθήκης σε ελεύθερη/πρόσθετη άσκηση. Η γρήγορη πληκτρολόγηση δημιουργεί ορισμό κατά την αποθήκευση. |
| `#progress-workout` | Επιλογή **προγράμματος** με value=`routineId`. Περιλαμβάνει και ελεύθερες/παλιές καταγραφές. |
| `#progress-exercise` | Ταυτότητες που ανήκουν στο επιλεγμένο πρόγραμμα ή στο ιστορικό του. |

Η Επίβλεψη διατηρεί ασκήσεις που αφαιρέθηκαν από το τρέχον πλάνο αλλά υπάρχουν στο ιστορικό του. Συγκεντρώνει διαφορετικές ημέρες και πολλαπλές εμφανίσεις της ίδιας άσκησης χωρίς να αναμειγνύει διαφορετικά IDs με ίδιο όνομα. Όλο το νέο στατικό κείμενο καλύπτεται σε ελληνικά, αγγλικά, γαλλικά και γερμανικά.
